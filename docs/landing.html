Why ShopKit

A system, not a pile of snippets

Every component reads from the same semantic tokens, so consistency is the default and theming is a one-line change. No build step required to consume it.

🎨

3-tier tokens

A raw ramp, a semantic layer, and per-component knobs. Components only ever read the middle tier, so restyling never means editing components.

🌗

First-class dark + multi-brand

Light, dark, system, and any number of brands on a single page — each scoped with one attribute, composing cleanly with mode.

🔁

RTL-safe, logical properties

Authored with inline/block logical properties throughout, so the entire UI mirrors correctly under dir="rtl" with zero extra CSS.

⚡

~19 KB, zero !important

Delivered on an @layer cascade, so your own unlayered CSS always wins — no specificity fights, no override hacks.

Get started

Two ways to install

Drop in the compiled stylesheet, or pull the Sass sources and compose your own build. Either way you get the same tokens, the same components, and the same public theming API.

CDN · one link tag

<!-- drop into your <head> -->
<link rel="stylesheet"
      href="https://cdn.jsdelivr.net/npm/shopkit/dist/shopkit.css">

npm · Sass sources

# install
npm install shopkit

// then, in your Sass entry
@use "shopkit/scss/shopkit";
