Layout · @layer sk.layout

Layout & the grid system

Three ways to build a row, in increasing order of control — a 12-column grid you pick spans from, a fixed n-column set that children just flow into, and a container-driven auto grid that needs no breakpoints at all. Every class below is real, compiled ShopKit. Grab the deck above and flip to RTL to watch the offsets mirror without a single extra rule.

Offsets & explicit lines new

.sk-col-start-* · .sk-col-end-*

A 12-column grid has 13 lines. Pin an item to one and it leaves a gap before it — that is the offset mechanism. .sk-col-start-5 + .sk-col-4 reads as “skip four columns, then span four”.

</div>
↹ Grid lines are inline-axis relative, so line 1 is the right edge under dir="rtl". Flip the Dir control in the deck — every offset above mirrors with no RTL-specific CSS.

Fixed column sets new

.sk-grid-cols-1 … -12

When every child takes exactly one track, a span class on each child is pure noise. Declare the track count once on the container instead — the children need no class at all. Responsive too: .sk-grid-cols-2 .sk-grid-cols-lg-5.

Auto grid new

.sk-grid--auto · --sk-grid-min

Responsive with zero media queries. You give an ideal minimum track width and the browser fits as many as the container allows. Because it reacts to the container rather than the viewport, it also reflows correctly inside a sidebar, a drawer or a modal — which breakpoints cannot do.

Row spans & dense flow new

.sk-row-* · .sk-grid--dense

Items can span rows as well as columns — the basis of any editorial or bento layout. .sk-grid--dense backfills the holes that wide items leave behind; toggle it below and watch the gaps close.

Shell layout new

.sk-shell · --sk-shell-rail

The two-column sidebar shape every docs site and admin screen needs — and the one this page is built with. The rail takes a fixed inline size, the content column takes whatever is left; below lg they stack, so no per-page media query is needed.

rail
content · minmax(0, 1fr)
<div class="sk-shell" style="--sk-shell-rail: 15rem">
  <nav class="sk-sidenav sk-sidenav--panel sk-sidenav--sticky" aria-label="Docs">
    <p class="sk-sidenav__title">ShopKit docs</p>
    <ul class="sk-sidenav__group">
      <li class="sk-sidenav__label">Pages</li>
      <li><a class="sk-sidenav__item" href="layout.html" aria-current="page">Layout</a></li>
    </ul>
  </nav>
  <main>…</main>
</div>
◆ The sidebar beside you is the real .sk-sidenav component. Its active row is driven by aria-current="page" — a genuine DOM signal, never a styling-only --active class — so the accessibility tree and the paint cannot drift apart. .sk-shell--end moves the rail to the visual end while leaving it first in the DOM for tab order.
